Maps mouse buttons and finger counts onto axes. On the core and in three.js it's an `InputControllerDom` from `@kvvasuu/klipp/dom` that takes the axes themselves. In React, `<InputController>` finds them by name in the piece it's placed in. Placed directly in a `<VirtualCamera>`, it finds them in any of the camera's pieces.

## Settings

| Setting | Description | Default |
| ------- | ----------- | ------- |
| `mouseButtons` | What each mouse button drives: `{ left, right, middle }`. | |
| `touches` | What each finger count drives: `{ one, two, three }`. | |
| `enabled` | Turns input on or off. | `true` |
| `suppressContextMenu` | Disable the right-click menu on the canvas. On `inputSystem` on the core and in three.js. | `false` |
| `interactiveArea` | Only start drags inside part of the canvas, as a normalized rectangle. On `inputSystem` on the core and in three.js. | whole canvas |
| `lockTouchAxis` | For two-finger gestures, pick either pinch or rotate instead of both. On `inputSystem` on the core and in three.js. | `false` |
| `waitForBlend` | Ignore input until the blend into this camera has finished. An option of `klipp.whileOnScreen` on the core and in three.js. | `true` |
| `target` | React only. A ref to something else with axes to control (for example a `PanTiltAimThree`), instead of the piece it's placed in. | parent piece, or the camera |

## Mapping a source

Each button or finger count takes the same config:

```ts
{
  axes: { x: 'pan', y: 'tilt' }, // which axis receives the horizontal and vertical drag: names in React, the axes themselves elsewhere
  gain: 0.15,                    // multiplier from pixels to axis units
  invert: { y: true },           // flip one or both directions, or `true` for both
}
```

## Pointer lock

For mouse look without holding a button, request pointer lock on the controller's `inputSystem`. While locked, mouse movement goes to `mouseButtons.left`.

## Raw input

`input` holds this frame's raw deltas, for example `wheelDeltaY`, `touchPinchDelta` or `leftDx`, if you want to handle something yourself.

```ts
import { InputControllerDom } from '@kvvasuu/klipp/dom';

const controller = new InputControllerDom({
  mouseButtons: { left: null, right: { axes: { x: aim.pan, y: aim.tilt }, gain: 0.15 }, middle: null },
  touches: { one: { axes: { x: aim.pan, y: aim.tilt }, gain: 0.15 }, two: null, three: null },
});
controller.inputSystem.suppressContextMenu = true;
klipp.whileOnScreen(camera, () => {
  controller.connect(canvas);
  return () => controller.disconnect();
});
klipp.registerUpdate(() => controller.update());
```

Every source has to be listed, `null` for unused ones. `whileOnScreen` connects it only while its camera is on screen, so several cameras don't react to the same drag. `controller.enabled = false` keeps it connected but ignores input.

**Pointer lock**

```ts
// in a click handler
controller.inputSystem.requestPointerLock();
controller.inputSystem.exitPointerLock();
```

**Raw input**

```ts
klipp.registerUpdate(() => {
  controller.update();
  zoom += controller.input.wheelDeltaY * 0.01;
});
```

```tsx
<Aim.PanTilt>
  <InputController
    mouseButtons={{ right: { axes: { x: 'pan', y: 'tilt' }, gain: 0.15 } }}
    touches={{ one: { axes: { x: 'pan', y: 'tilt' }, gain: 0.15 } }}
    suppressContextMenu
  />
</Aim.PanTilt>
```

Input is only read while its camera is on screen. `ref` gives you the `InputControllerDom`.

**Pointer lock**

```tsx
const controller = useRef<InputControllerDom>(null);

<InputController ref={controller} mouseButtons={{ left: { axes: { x: 'pan', y: 'tilt' } } }} />;

// in a click handler
controller.current.inputSystem.requestPointerLock();
controller.current.inputSystem.exitPointerLock();
```

**Raw input**

```tsx
useFrame(() => {
  zoom += controller.current.input.wheelDeltaY * 0.01;
});
```
