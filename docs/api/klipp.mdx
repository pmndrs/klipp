The camera director: it runs every [virtual camera](/api/virtual-camera), picks the winner, blends between shots, and puts the result on your camera.

`Klipp` works with any renderer: put its `shot` on your camera after `update`. Integrations write it for you, like `KlippThree` for three.js and `<Klipp>` for React Three Fiber.

## Members

| Member | Description |
| ------ | ----------- |
| `add(camera)`, `remove(camera)` | Adds or removes a [virtual camera](/api/virtual-camera). Adding moves it from any other klipp. |
| `update(dt)` | Runs one frame. Returns `true` while something is still moving or the shot changed. |
| `shot` | The current shot, see below. |
| `setSize(width, height)` | The viewport size in CSS pixels, for pieces that frame by screen position and for panning [`KlippControls`](/controls/klipp-controls). |
| `orthographic` | Whether the camera being driven is orthographic. See [Orthographic cameras](#orthographic-cameras). |
| `defaultBlend`, `customBlends` | The blends, changeable at any time. |
| `registerUpdate(fn)` | Runs `fn` every frame before the cameras, for input. Returns a function that stops it. |
| `requestFrame()` | Asks for one more frame, through `subscribeFrameRequest`. |
| `subscribeFrameRequest(listener)` | Calls `listener` when something changes between frames, for a loop that runs only [on demand](/advanced/on-demand-rendering). Returns a function that stops it. |
| `mode` | `'enabled'`, `'standby'` or `'disabled'`. See below. |
| `activeCameraName`, `isActive(name)` | The winner, the camera the shot is heading to. |
| `activeCameraState` | The winner's own state, before blending. |
| `liveCameraName`, `isLive(name)` | The camera fully on screen, once the blend into it has finished. |
| `isBlending` | Whether a blend is in progress. |
| `weightOf(name)` | The share of the camera named `name` in the shot, from `0` to `1`. A camera in a group has its own [`screenWeight`](/api/virtual-camera#members). |

Klipp is also an event target, see [Events](/api/events).

## `mode`

| Mode | Cameras update | Camera is written |
| ---- | -------------- | ----------------- |
| `'enabled'` | yes | yes |
| `'standby'` | yes | no |
| `'disabled'` | no | no |

Use `'standby'` to hand the camera to something else for a while (an editor, a photo mode). Klipp keeps its cameras updated in the background, so they're ready the moment you switch back.

## The shot

`shot` is a `CameraState`:

| Field | Description |
| ----- | ----------- |
| `position`, `quaternion` | Where the camera is and how it's turned: `[x, y, z]` and `[x, y, z, w]`. |
| `fov`, `near`, `far` | Lens settings, `fov` in degrees. |
| `orthographicSize` | Half the view's height in world units, used by an orthographic camera instead of `fov`. |
| `viewOffset` | Shifts the view without moving the camera, as a fraction of half the viewport. `[0, 0]` is centered. |

To react only when `shot` changes, override `write`, see [Building on the core](/getting-started/building-on-the-core#your-own-integration).

## Orthographic cameras

An orthographic camera shows `orthographicSize` world units above and below the center of the view, at any distance. Each virtual camera has its own size, like its `fov`: set it with [`Lens`](/extension/lens) or in `initialState`, and blends move between sizes.

`orthographic` tells the pieces whether the camera being driven is orthographic. `KlippThree` and `<Klipp>` set it from their camera, also when it is swapped, for example for drei's `<OrthographicCamera makeDefault>`. On the core, set it yourself.

`KlippThree` writes the size through the camera's `zoom`, so after a resize the same part of the world stays in view. New virtual cameras start from the size of the camera `KlippThree` was created with, like `<Canvas orthographic camera={{ zoom: 50 }}>`.

`Klipp` works with any renderer. Call `update` every frame and put `shot` on your camera:

```ts
import { BlendCurves, Klipp, VirtualCamera } from '@pmndrs/klipp';

const klipp = new Klipp({ defaultBlend: { curve: BlendCurves.easeInOut, time: 1 } });
klipp.setSize(canvas.clientWidth, canvas.clientHeight);
klipp.add(new VirtualCamera('main', { priority: 10 }));

function frame(dt: number) {
  if (klipp.update(dt)) {
    engine.camera.setTransform(klipp.shot.position, klipp.shot.quaternion);
    engine.camera.setFov(klipp.shot.fov);
    engine.render();
  }
}
```

New cameras start from `initialCameraState`, an option of `Klipp`. Pass your camera's starting pose there. For an orthographic camera, set `orthographic` to `true` and use `shot.orthographicSize` instead of `fov`.

`KlippThree` is `Klipp` driving a three.js camera. `update` writes the shot to it:

```ts
import { BlendCurves } from '@pmndrs/klipp';
import { KlippThree, VirtualCameraThree } from '@pmndrs/klipp/three';

const klipp = new KlippThree(camera, { defaultBlend: { curve: BlendCurves.easeInOut, time: 1 } });
klipp.setSize(innerWidth, innerHeight);
klipp.add(new VirtualCameraThree('main', { priority: 10 }));

renderer.setAnimationLoop(() => {
  klipp.update(dt);
  renderer.render(scene, camera);
});
```

New cameras start from the camera's lens, position and rotation at the time `KlippThree` is created. It drives a `PerspectiveCamera` or an [`OrthographicCamera`](#orthographic-cameras), and `klipp.camera` can be swapped at any time: the new camera gets the shot on the next frame.

  </TabsContent>
  <TabsContent value="r3f">

`<Klipp>` creates a `KlippThree` on the React Three Fiber camera and runs it every frame. It has to be inside `<Canvas>`.

```tsx
import { BlendCurves } from '@pmndrs/klipp';
import { Klipp } from '@pmndrs/klipp/react';

<Canvas>
  <Klipp defaultBlend={{ curve: BlendCurves.easeInOut, time: 1 }}>
    <VirtualCamera name="main" priority={10}>...</VirtualCamera>
  </Klipp>
</Canvas>
```

| Prop | Description | Default |
| ---- | ----------- | ------- |
| `defaultBlend` | How to blend between cameras. See [Blending](/blending/introduction). | `{ curve: BlendCurves.easeInOut, time: 2 }` |
| `customBlends` | Blends for specific camera pairs. See [Custom blends](/blending/introduction#custom-blends). | `[]` |
| `camera` | The camera to drive. | the r3f default camera |
| `mode` | `'enabled'`, `'standby'` or `'disabled'`. See [`mode`](#mode). | `'enabled'` |

Virtual cameras start from the real camera's lens, position and rotation, so whatever you set on `<Canvas camera={...}>` is the starting point. `<Canvas orthographic>` works too, see [Orthographic cameras](#orthographic-cameras). It keeps the viewport size in sync for you.

[`useKlipp()`](/api/hooks#useklipp) gives you the `KlippThree` behind `<Klipp>`, with the members above, and [`<Klipp.Events>`](/api/events) listens to every transition.
